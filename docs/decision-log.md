# Decision log

Decisions I made and why, problems I ran into, and how I fixed them. Oldest first. Anyone working on this (people or AI agents) should add to this as they go: one bullet per item, starting with the date.

- 2026-11-05: Set up the first tables (allergens, ingredients, recipes, products, restaurants, menu items). Products and menu items get a level for each allergen, either "contains" or "may contain", since that's how food labels usually say it.
- 2026-11-08: Added Open Food Facts (OFF) columns to products: ingredient tags, allergen tags, trace tags ("may contain"), OFF's completeness score, and when the product was last edited. Added an index on ingredient tags so checking if a product has an ingredient is fast.
- 2026-11-08: Renamed those columns so they aren't tied to OFF (for example off_allergen_tags became allergen_tags), and made barcodes unique per data source instead of across everything, so other data sources can fit in later.
- 2026-11-08: The import crashed with "null value in column id". DuckDB copies rows into Postgres in a way that skips the automatic id. Fixed it by loading rows into a staging table first, then letting Postgres copy them into product so it makes the ids itself.
- 2026-11-08: The import now deletes the old OFF products and inserts the new ones in one transaction, so if something fails halfway the table doesn't end up empty.
- 2026-11-08: Running several SQL commands in one postgres_execute call doesn't work (it only takes one command at a time). Split them into separate calls.
- 2026-11-08: Calling fetchone() on conn.sql(...) doesn't work in this version of DuckDB. Use conn.execute(...) instead.
- 2026-11-08: The data file path is relative, so the import script has to be run from the backend folder.
- 2026-11-08: The allergen part of the import was Postgres SQL being run by DuckDB, so it couldn't find the tables. Fixed by running it through postgres_execute like the rest.
- 2026-11-08: Counting rows through DuckDB in the middle of the import transaction gave wrong numbers (not 0 and not the full count). Asking Postgres directly gave the right answer. So don't read tables through DuckDB inside that transaction.
- 2026-11-08: Product ids change every time the import reruns, and deleting a product also deletes its allergen rows. So the import rebuilds the whole product_allergen table every time.
- 2026-11-08: The allergen_rule table was empty, so no product got any allergens. Wrote and tested 328 match patterns (like %whey% for milk) to fill it.
- 2026-11-08: Simple text matching had a lot of traps. "oat milk" also matched "goat milk", "no peanut" matched "jalapeno peanuts", the French word for egg (oeuf) matched beef (boeuf), and "ground nut" matched nutmeg. Each one needed its own fix, which showed how easy it is to get this wrong.
- 2026-11-08: Some OFF tags are general categories added on top of the real ingredient. For example every peanut also gets tagged as "nut", so "nut" can't be used as a sign of tree nuts. And OFF's "gluten" tag isn't just wheat, it also covers barley, rye, and oats.
- 2026-11-08: Matching in Postgres is case sensitive, so tags written in capitals (like "VITAL WHEAT GLUTEN") were missed.
- 2026-11-08: Some labels put warnings like "made in a facility that processes peanuts" inside the ingredient list. The import was counting those as "contains" when they should be "may contain".
- 2026-11-08: With all 328 patterns, building the allergen table took about 3.7 minutes, compared to about 26 seconds for the rest of the import.
- 2026-11-11: Decided to switch from match patterns to a lookup table. Each ingredient tag gets checked once (by an AI model, then spot checked by me) and saved as tag to allergen. It's easier to read, easier to fix one wrong tag, and much faster. The 5,000 most common tags cover about 96% of all tag uses, so most of the data is handled without classifying every one-off typo. OFF's own allergen and trace tags stay as a backup for the rest.
- 2026-11-11: I'm writing the lookup table code myself so I learn how it works. AI help is for explaining and reviewing, not writing it.
- 2026-11-11: Started this decision log and a TODO list in the docs folder.
- 2026-11-11: Got confused about what state the migrations were in after redoing them a few times. Since the database only lives on my laptop, the migration files are what counts. If I'm unsure, I can rebuild the database from them with npx supabase db reset and rerun the import.
- 2026-11-11: Coconut doesn't count as a tree nut, since the FDA stopped counting it in January 2025.
- 2026-11-11: Gluten is its own allergen now. Wheat counts as gluten, but gluten isn't just wheat, so barley, rye, and malt get flagged as gluten too. Regular oats get "may contain" gluten because they're almost always cross-contaminated. Before this, OFF's gluten tag was being counted as wheat, which flagged about 5,400 products as wheat when most of them were really barley, rye, or oats.
- 2026-11-11: Peanut oil counts as peanut, even highly refined peanut oil. Labeling law doesn't count refined oils, but I've reacted to peanut oil the same as peanuts. Later the app could let users choose.
- 2026-11-11: The lookup table will be two tables, tag and tag_allergen, set up the same way as ingredient and ingredient_allergen. A tag that was checked and has no allergen still goes in tag, so I can tell "checked, nothing found" apart from "never checked".
- 2026-11-11: I don't have an AI API key, so instead of a script calling an AI, a separate Claude session will classify the tags by hand following docs/classify-tags.md. The tag list is the 23,343 tags used by 5 or more products, which covers about 97.5% of all tag uses.
- 2026-11-11: Saved the old 328 pattern rules to backend/lookup/old_allergen_rules.json, so they can be used to double check the lookup table.
- 2026-11-11: Claude classified all 23,343 tags into backend/lookup/tag_allergen.csv. About 4,000 tags got at least one allergen and the rest are "none". Every input tag is in the file, and 18 of the 20 test tags in docs/classify-tags.md came out right. The other two (en:jalapeno-peanuts and en:may-contain-peanuts) aren't in the tag list because fewer than 5 products use them.
- 2026-11-11: OFF's en:flour tag is added to almost every flour, including rice and corn flour, the same way en:nut is added to peanuts. So it's labeled none, like en:nut. Only about 1,600 products have plain "flour" with no more specific flour tag. It's marked unsure because plain "flour" on a US label usually means wheat.
- 2026-11-11: A lot of common tags were never caught by the old patterns, like soy sauce (wheat), white chocolate (milk), half-and-half, fontina, gorgonzola, and pepper jack. Several "butter" tags the old patterns flagged as milk are really plant fats, like cocoa butter typos, shea butter, sal butter and SunButter. Plant milks like flax milk and sesame milk were wrongly flagged too.
- 2026-11-11: When a tag doesn't say what it's made of (crust, dough, gravy, noodle, wrapper, tortilla, multigrain blend), Claude flagged the usual allergen and marked it unsure. The same goes for butter, cheese and nut flavorings, non-dairy creamers (they often have caseinate), and baby formula sugars like 2'-FL that are made from lactose.
- 2026-11-11: Following the oat milk rule, oat milk, oat base and oat milk powder are none, even though oats are normally "may contain" gluten. That might be worth changing.
- 2026-11-11: The tags where Claude disagreed with the old rules are in docs/tag-review-disagreements.csv (971 tags), and the unsure ones are in docs/tag-review-unsure.csv (612 tags), both sorted by how many products use them.
- 2026-11-12: I'm not an expert and can't check every label by hand, so for now Claude's labels stand, and we can change them later. The general rule is to keep labels open: when unsure, flag the likely allergen but mark it unsure, so the app can give it a lower confidence instead of hiding the product. That way people with several allergies still get more options.
- 2026-11-12: en:flour and en:wholemeal-flour are now wheat and gluten, marked unsure. Plain "flour" usually means wheat. The catch is that OFF also adds these tags to rice, corn and oat flour, so about 21,000 products without a wheat tag will get a low-confidence wheat flag.
- 2026-11-12: Oat milk (and oat base, oat milk powder, oat drink and oat butter) is now gluten "may contain", like regular oats. This changes one of the test answers in docs/classify-tags.md, which said oat milk should be none.
- 2026-11-12: Added an unsure column to tag_allergen in the tutorial, filled in from the note column of the lookup file, so the confidence information isn't lost.
- 2026-11-12: The backend uses uv for Python packages and FastAPI for the API. The frontend will be a React website made with Vite (TypeScript), styled with Tailwind so I write style classes right in the components instead of keeping one huge CSS file.
- 2026-11-14: Claude went through all 23,343 tags again for soy, fish and shellfish, and merged the results into backend/lookup/tag_allergen.csv. 976 tags got at least one of the three (577 soy rows, 250 fish, 163 shellfish), and their old "none" rows were removed. The rows for the first seven allergens didn't change, and every input tag is still in the file. 11 of the 14 test tags came out right. The other three (en:soybean-oil, en:soy-lecithin and en:crayfish) aren't in the tag list, because OFF uses en:soya-oil, en:soya-lecithin and en:crawfish instead, and those came out right.
- 2026-11-14: Soybean oil and soy lecithin count as soy, but marked unsure, since they're refined and most people with a soy allergy can eat them. This is the same idea as peanut oil, but with lower confidence. These two are some of the most common tags in the whole list (each is on about 50,000 products), so this flags a lot of products.
- 2026-11-14: OFF's E322 tags (lecithin, no source given) are on about 68,000 products each. Most of the time that's soy lecithin, so they're soy, marked unsure. Sunflower, canola and rapeseed lecithin are none.
- 2026-11-14: Mollusks (clam, oyster, scallop, squid and so on) count as shellfish but are marked unsure. US law only counts crustaceans like shrimp and crab, but a lot of people with shellfish allergies avoid both.
- 2026-11-14: Some things that don't look like seafood got flagged unsure: Thai curry pastes (they usually have shrimp paste), kimchi (fish sauce and salted shrimp), imitation crab (it's fish, but can have real crab), crickets and cricket flour (people with shellfish allergies can react to insects), and omega-3, DHA and EPA with no source (often fish oil, but can be algae).
- 2026-11-14: The same tag sometimes shows up twice, once with spaces and once with dashes (like "light tuna" and "light-tuna"). Two of those got missed on the first look and were caught by a keyword check at the end.
- 2026-11-14: The 412 unsure tags from this pass are in docs/tag-review-unsure-new.csv, sorted by how many products use them. About 245 of them are just refined soybean oil or soy lecithin.
- 2026-11-15: The product_allergen insert ran for over 25 minutes without finishing. Postgres plans queries using saved stats about each table, and the tag tables had just been filled in the same transaction, so it thought they were nearly empty and picked a plan that paired every product with every tag. Running ANALYZE on product, tag and tag_allergen right before it fixed it. Also, ANALYZE can take several tables in one command, which matters since postgres_execute only takes one command at a time.
- 2026-11-15: Wrote docs/tutorial-prototype.md for the Sprint 5 plan prototype. It saves hand-picked products by barcode instead of product id, since ids change on every import. It also treats 'may contain' as unsafe for now and rejects misspelled allergen names, because a typo like "peanuts" would otherwise match nothing and make everything look safe.
